## Goal

The 2.0 contract types and Zod schemas exist exactly as specified, and a real TCGdex lookup returns a validated `CardPrinting` — the foundation every other ticket builds on.

## Context

- Read: `context/pokepal-2/02-target-architecture.md` §Domain boundaries, §Catalog provider decision
- Relevant area: `src/types/`, `src/lib/catalog/` (new), `package.json`

## Changes

- Add `src/types/catalog.ts`, `collection.ts`, `scan.ts` verbatim from the contract, plus Zod schemas.
- `src/lib/catalog/`: `CatalogProvider` interface; TCGdex adapter (`getPrinting(id, lang)`, `findByNumber(collectorNumber, setOfficialCount, lang)`, `searchByName(name, lang)`), mapping TCGdex → `CardPrinting` (energy-type mapping, `dexId` → `dexNos`, variants → `availableFinishes`, missing image → `null`, pricing dropped); static `dexNo → region` table.
- Add `vitest` as a dev dependency and an `npm test` script (decision D6).
- Recorded TCGdex responses under `test/fixtures/tcgdex/` (incl. `swsh3-20`, a no-image card such as `30th-c-001`, a trainer, a Japanese card) — tests run offline against them.

## Verification

- `npm test`: mapping tests pass on recorded fixtures (exact fields, no pricing keys, null image handled).
- One opt-in live check (`LIVE_CATALOG=1 npm test`) fetches `swsh3-20` from TCGdex and validates it.
- `npm run lint` and `npm run build` pass; no UI change.

**Repair notes (worker 18.1, 2026-10-09, from reviewed head `ddb7504`):**

- Per decision D10: `CatalogLanguage` is `"en" | "es" | "ja"`; `CardPrinting.id` is `tcgdex:{language}:{providerCardId}` and the schema enforces it. Contract block and dated note updated in `02-target-architecture.md`.
