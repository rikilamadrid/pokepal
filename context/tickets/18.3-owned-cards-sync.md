# Sync owned cards to Supabase with owner guard

## Status

Proposed

## Parent Feature

`18-catalog-backed-collection.md`

## Blocked by

- `18.2` — local OwnedCard store

## Goal

Signed-in owned cards back up and sync across devices through a new additive `owned_cards` table, and a different user on the same device never receives or pushes another user's cards.

## Context

- Read: `02-target-architecture.md` §Persistence; `src/lib/sync.ts`, `src/hooks/useSync.tsx`, `src/lib/supabase-cards.ts`, `prisma/`, `context/features/phase-16-account-privacy-spec.md`

## Changes

- Prisma model + migration for `owned_cards` (additive) and an idempotent RLS SQL file; rollback note.
- Pure reconcile for owned cards (reuse the LWW/tombstone logic; no image handling) + row mappers.
- Owner guard: never push rows whose `ownerId` is another user's; account-change reset per phase-16 for 2.0 data.
- Legacy `cards` sync unchanged.

## Verification

- `npm test`: reconcile cases + owner-guard cases.
- Migration verified against a local/branch Supabase database (`prisma migrate dev`); live apply only after gate D9.
- Two-session manual check recorded.

## Out of Scope

- Applying the migration to the live project without approval. Legacy photo migration.

## Notes / Decisions

- Gate D9 (live migration) is a human gate on this ticket.
