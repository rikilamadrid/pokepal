# recognize-cards Edge Function + evaluation harness (budget-capped)

## Status

Proposed

## Parent Feature

`19-card-recognition.md`

## Blocked by

- `19.1` — resolver and recognition client

## Goal

A non-production Supabase Edge Function turns a card photo into a `ScanBatch` using a cost-efficient Claude vision model, and an evaluation harness can measure it under a hard €5 cap.

## Context

- Read: `02-target-architecture.md` §Recognition pipeline, §Image lifecycle, D2/D5; `context/ai-interaction.md` §PokéPal 2.0 approvals

## Changes

- `supabase/functions/recognize-cards/`: JWT verification, per-user rate limit, structured-output prompt, Zod validation, server-side resolve via the shared resolver, no logging of bodies, key from secrets only.
- `edgeTransport` wired in the client module.
- `evals/recognition/`: runner over a labelled fixture manifest (photo path → expected printing ids), budget ledger that refuses to start or continue past €5, report writer (accuracy, ambiguity, wrong-match, p50/p95 latency, cost/photo).
- Dry-run mode that exercises everything except the paid call.

## Verification

- `npm test`: prompt/response schema tests, budget-ledger refusal test, no-logging check.
- Dry run of the harness passes with zero paid calls.
- Paid run only after the human confirms key + spend limit (human gate).

## Out of Scope

- Production deploy. Real-photo evaluation run (19.3).

## Notes / Decisions

- Human gate: API key + spend-limit confirmation before any paid call.
